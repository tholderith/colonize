# Art Samples — Shared Spec

Goal: render the **same harbour-town scene** in several art styles × several engines so
we can choose an art direction and a tech stack for the game (working title "Colonize":
Anno-style production chains + Colonization-style crown/independence arc, set in a
fictional age-of-sail archipelago, real-time with pause).

Everything here is the contract between art and engines. Do not change it unilaterally.

## Directory layout

```
art-samples/
  SPEC.md                    this file
  scene/layout.json          the scene (generated by tools/gen_layout.py — do not hand-edit)
  styles/<style>/manifest.json + PNGs      one folder per art style
  engines/<engine>/          one self-contained project per engine
  renders/<engine>/<style>.png             1920x1080 output, one per style
  tools/render_ref.py        reference renderer (Python/PIL) — the source of truth for semantics
```

## Coordinate system (isometric 2:1)

- Tile diamond: **128 × 64 px**.
- Map is `width × height` tiles (20 × 20). `terrain[y][x]` is a char; see `terrain_legend`.
- Output image: **1920 × 1080**.
- Screen position of the **top corner** of tile (x, y):
  `sx = 960 + (x - y) * 64`, `sy = -72 + (x + y) * 32`
  (this puts the centre of tile (10,10) at screen (960, 600)).
- The **south corner** (bottom vertex) of tile (x, y) is `(sx, sy + 64)`.
- 3D-rendered styles: use an orthographic camera at **yaw 45°, pitch 30°** below
  horizontal (sin 30° = 0.5 gives the exact 2:1 diamond). Note: atan(0.5) ≈ 26.57° is the
  slope of the diamond's edges on screen, not the camera pitch.

## Sprites and anchors

Every sprite is a PNG with an **anchor** pixel `[ax, ay]`. To draw a sprite at a
screen point P, place its top-left at `P - anchor`. Sprites are drawn 1:1 (no scaling).

- **Terrain** sprite for tile (x,y): P = south corner of that tile.
  A flat terrain tile is a 128×64 diamond with anchor `[64, 64]`. Taller tiles (e.g.
  grass tufts or a beach lip) are allowed — keep the anchor at the diamond's south corner.
- **Object** with footprint (fw, fh) placed at (x, y): P = south corner of tile
  `(x + fw - 1, y + fh - 1)`. For a 2×2 object the footprint diamond is 256×128,
  so a flat 2×2 sprite would have anchor `[128, 128]`.

### Variants

A sprite entry lists one or more files. For an item at tile (x, y) use
`files[(x * 7 + y * 13) % len(files)]`.

## Draw order

1. Clear to the manifest's `background` colour.
2. Terrain, for all tiles, ordered by `(x + y)` ascending, then `x` ascending.
3. Objects whose sprite has `"flat": true`, in layout order.
4. Remaining objects sorted by depth `(x + fw - 1) + (y + fh - 1)` ascending, then by
   `x + fw - 1` ascending, then by layout order (stable).
5. Overlays (screen-space UI etc.) in manifest order: P = `pos`, honouring `anchor`.

Texture filtering: `"filter": "linear"` (default) or `"nearest"` (pixel art).

## manifest.json

```json
{
  "name": "Painted Isometric",
  "background": "#1b4a66",
  "filter": "linear",
  "sprites": {
    "grass": { "files": ["grass_0.png", "grass_1.png"], "anchor": [64, 64] },
    "wheat_field": { "files": ["wheat.png"], "anchor": [128, 128], "flat": true }
  },
  "overlays": [
    { "file": "ui_topbar.png", "pos": [0, 0], "anchor": [0, 0] },
    { "file": "ui_panel.png", "pos": [24, 1056], "anchor": [0, 300] }
  ]
}
```

Paths are relative to the manifest. Overlays are required to include a **top resource
bar** (full width, ~64–80 px tall, showing icons + numbers for e.g. gold, wood, bricks,
tools, food, cloth, population) and a **building info panel** (~360×300, bottom-left,
showing e.g. the warehouse's stock or a house's needs). The UI is part of the art
direction — it should match the style. Optional extra overlays (vignette, paper grain)
are allowed.
